At a glance

Is it for you?

For an organization that wants to manage its own user directory and sign-in across connected applications, with control over who can access each one.

How you use it
Run the server with Docker Compose and a persistent data volume. Configure a stable public HTTPS address and register the applications you want to connect.
Availability
Server source and setup documentation are available. KyIdentity is designed for a single organization; consult the repository for current integration requirements.

Inside KyIdentity

Give access a clear home.

01

Manage people and apps

Invite users, organize groups, and assign access to applications. An app launcher gives people a place to find their connected tools.

02

Strengthen sign-in

Use authenticator codes, paired-device push approval, or passkeys as a second factor. Recovery codes help people regain access when a factor is lost.

03

Connect your software

OpenID Connect provides shared sign-in. Configured provisioning connections can keep downstream accounts and groups in sync, including supported SCIM integrations.

How KyVault uses KyIdentity

KyVault requires KyIdentity for sign-in. Your KyVault master password has a separate job: it unlocks your vault key in your browser. Signing in and decrypting the vault are distinct steps.

If KyIdentity is unavailable, new KyVault sign-ins are unavailable too. Prepare KyVault’s offline access in advance with a downloaded vault and its Offline Vault Key.

For administrators

Know who has access, and why.

Access by user or group

Assign people directly or through groups, map application roles, and preview effective access. Each connected application still needs to enforce the permissions it receives.

Account lifecycle

Manage invitations, password resets and account deactivation. Configure email delivery for mailed invitations and self-service resets; without it, an administrator hands over activation links.

An audit trail

Search recorded events by actor, action, time and outcome, and export filtered records. Use the log to investigate access changes and administrative activity.

Running your own identity service

A foundation to look after.

A stable address

Use HTTPS and choose the service address before enrolling devices and connecting applications. Changes to the identity service’s address can affect existing integrations and passkeys.

Backups and recovery

Protect the database and deployment keys, plan administrator recovery, and follow the project’s backup and restore instructions. KyRecovery integration supports sealed backups.

Integration matters

Register application callback addresses exactly. Account revocation and sign-out also depend on the receiving app’s token and session handling; a launcher link alone does not secure that app.

Your directory, your responsibility

The operator manages accounts, authentication factors, app connections and audit records, and is responsible for access, updates and retention. Connected apps receive identity information according to their configured scopes and roles.

Read the Busnes.app privacy policy. For data held by an independently operated KyIdentity installation, contact its operator.
