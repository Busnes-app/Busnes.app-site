Shared maintenance and release limits

The November 16–17 dependency pass refreshed compatible versions and bumped application patch versions. Shared-library pins newer than stable tags were retained, and SQLite stays paired with its required libc/runtime dependencies. Later patch releases and catalog pins may be newer than the initial 0.6.1 rollout; use the installer’s checked catalog, not this page as an image-version matrix. The server base was outside that coordinated app pass.

Twenty public manuals were published on November 16 with source revisions recorded in the manual catalog. Nineteen product snapshots remain intact. The KyPost book is refreshed for the identity product naming correction, with its new source commit recorded in the catalog. The new suite connections guide describes cross-app tasks from the source review above; it does not silently repin the individual product books. Read the linked repository guides for later changes and exact commands.

Recent security changes need compatible server and client versions. In particular, current Drive servers require device signatures and older links may need re-linking. Preserve server identity keys and configure the public certificate-chain source for signed rollover. KyAuth’s proof-based QR enrollment differs from its short-PIN fallback, and supported app sign-on now requires the consumer’s proof key. These mechanisms have different trust boundaries; see the security summary.

What this review does not claim

  • Native KyPost receiving/direct delivery is implemented but not a whole workforce-mail qualification. Preserve the deployed provider/relay path until the intended mode is tested.
  • Installer upgrade and recovery fixtures cover their documented cases, not every provider, edge, physical device, storage driver or a production stack’s complete restore.
  • Calendar PostgreSQL deployments still require their own protected database backup; SQLite capsules do not cover that driver. Drive files, Matrix media/keys and Notes blobs have additional recovery requirements.
  • Android Drive’s roadmap is not its current feature list. Its document provider, persistent offline files and automatic photo backup are not shipped features.
  • Historical UI review scores, generated screenshots, manuals, badges and passing builds are not evidence of a new production deployment or independent security audit.
